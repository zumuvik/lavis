# Lavis

[![CI](https://github.com/zumuvik/lavis/actions/workflows/ci.yml/badge.svg)](https://github.com/zumuvik/lavis/actions/workflows/ci.yml)
[![Лицензия: GPL-3.0-only](https://img.shields.io/badge/License-GPL--3.0--only-blue.svg)](LICENSE)
![Rust](https://img.shields.io/badge/Rust-stable-orange.svg)
![NixOS](https://img.shields.io/badge/NixOS-supported-5277C3.svg)

Lavis — личный Telegram userbot на Rust, использующий MTProto через grammers. Основная платформа — Linux/NixOS; команды принимаются из сообщений, автором которых является авторизованный аккаунт, включая собственные «Сохранённые сообщения», если Telegram помечает их как не исходящие.

## Возможности

- интерактивная авторизация и локальное хранение MTProto-сеанса;
- обработка новых и отредактированных сообщений, автором которых является авторизованный аккаунт, включая собственные «Сохранённые сообщения», помеченные Telegram как не исходящие;
- редактирование исходного сообщения ответом и подавление ожидаемых собственных редактирований, чтобы не возникали циклы;
- сохраняемые префикс и псевдонимы;
- реальная проверка задержки MTProto командой `ping` и статистика времени работы;
- ограниченный запуск `fastfetch`;
- контекстная русскоязычная справка Help v2;
- статический реестр внутренних модулей Core, System и Aliases с метаданными Module API v1;
- внешние модули на любом языке через JSON-line protocol;
- проверяемая установка `.lmod` из «Сохранённых сообщений» с отдельным подтверждением и atomic no-overwrite commit.

## Команды

| Команда | Назначение |
| --- | --- |
| `help` | Контекстная справка по командам и модулям. |
| `modules` | Список внутренних и активных внешних модулей. |
| `ping` | Проверка задержки MTProto. |
| `prefix` | Просмотр, изменение или сброс префикса. |
| `stats` | Статистика работы. |
| `fastfetch` | Ограниченный вывод системной информации. |
| `alias` | Управление псевдонимами. |
| `setup` | Создание и восстановление companion-бота из «Сохранённых сообщений». |
| `lm` | Просмотр, проверка и установка внешних `.lmod`-модулей. |

Префикс по умолчанию — запятая (`,`). Примеры используют текущий настроенный префикс: после его изменения используйте новый префикс.

```text
,help
,help ping
,help lm
,help core
,modules
,lm list
,ping
,stats
,prefix
,prefix .
.prefix reset
,fastfetch
,alias add sys fastfetch
,sys
```

Настройка companion-бота описана отдельно: [Companion bot setup](docs/companion-bot-setup.md).

## Внутренние модули

Группы команд статически скомпилированы в программу и не являются устанавливаемыми плагинами. Module API v1 связывает каждую команду с модулем, русскоязычными описаниями, примерами, уровнем риска и заявленными возможностями. Help v2 строит обзор и карточки команд, модулей и псевдонимов по этому реестру; примеры в метаданных не содержат префикса, а интерфейс подставляет текущий префикс.

- **Core:** `help`, `modules`, `ping`, `prefix`, `setup`, `lm`, `stats`
- **System:** `fastfetch`
- **Aliases:** `alias`

Подробности для пользователей и разработчиков: [Module API v1](docs/module-api-v1.md). Правила участия в проекте: [CONTRIBUTING.md](CONTRIBUTING.md).

Module API v1 сам по себе остаётся статическим контрактом встроенного реестра. Внешний runtime, installer и protocol описаны отдельно в Module API v2/v3 и не превращают `ModuleOrigin::External` из v1 в загрузчик кода.

## Внешние модули (alpha)

Внешний модуль — отдельная исполняемая программа на любом языке. Lavis запускает включённые модули как дочерние процессы и обменивается с ними JSON-строками через stdin/stdout. Поддерживаются manifest schema/protocol 2 и 3.

### Установка `.lmod` через Telegram

1. Соберите модуль как stored ZIP-архив с расширением `.lmod`; `module.json` должен находиться в корне архива.
2. В «Сохранённых сообщениях» прикрепите `.lmod` к новому исходящему сообщению с текстом `,lm install`.
3. Lavis скачает архив с жёстким лимитом, проверит структуру, manifest, права и entrypoint и покажет inspection plan.
4. В течение 10 минут подтвердите полный одноразовый ApprovalId командой `,lm confirm XXXX-XXXX-XXXX-XXXX` или отмените план через `,lm cancel XXXX-XXXX-XXXX-XXXX`.
5. Установленный модуль остаётся выключенным. Включите его локально командой `lavis modules enable <id>` и перезапустите Lavis.

```bash
# Локальная CLI
lavis modules validate ./my-module/module.json
lavis modules enable my-module
lavis modules disable my-module
lavis modules status

# Telegram
,lm
,lm list
,my-module.command-name аргументы
```

Schema 3 дополнительно поддерживает `default_command`, подписку `message.created`, контекст custom emoji и ограниченное действие `message.react` при явно заявленных capabilities.

Документация:

- [External Modules](docs/external-modules.md) — полный пользовательский и разработческий workflow;
- [Module API v2/v3](docs/module-api-v2.md) — manifest и JSON-line protocol;
- [Packaging `.lmod`](docs/lmod-packaging.md) — формат архива, лимиты и безопасная упаковка;
- [examples/external-module-echo/](examples/external-module-echo/) — минимальный пример.

**Предупреждение:** внешние модули запускаются без системной песочницы и с правами пользователя Lavis. Capabilities являются описательными метаданными, а не механизмом изоляции. Устанавливайте и включайте только доверенный код.

## Требования

- Linux; текущие outputs Nix flake предназначены только для `x86_64-linux`;
- Telegram API ID и API hash, полученные на [my.telegram.org](https://my.telegram.org/);
- Rust — только для сборки из исходного кода;
- Nix flakes рекомендуются;
- Nix-пакет и dev shell предоставляют `fastfetch` в `PATH`; для отдельной сборки Cargo `fastfetch` нужно установить в `PATH` самостоятельно.

## Учётные данные Telegram

При первом запуске Lavis интерактивно запрашивает API ID и API hash. Они сохраняются в `credentials.json`: `$XDG_CONFIG_HOME/lavis/credentials.json`, а при отсутствии `XDG_CONFIG_HOME` — в `$HOME/.config/lavis/credentials.json`. Каталог конфигурации создаётся с правами `0700`, файл — с правами `0600`.

Переменные `LAVIS_API_ID` и `LAVIS_API_HASH` — необязательное расширенное переопределение. Для него должны быть заданы обе переменные; частичная пара является ошибкой, а переменные окружения и `credentials.json` не смешиваются. Не используйте для обычной работы файлы окружения, `source`, `chmod` или экспорт переменных: интерактивное хранение в `credentials.json` является штатным способом.

Не публикуйте и не добавляйте в Git API hash или `credentials.json`.

## Запуск через Nix

```bash
nix run github:zumuvik/lavis
```

Команда запускает Lavis и при необходимости проводит первичную настройку. После клонирования репозитория можно выполнить `nix run`. Для разработки из исходного кода используйте:

```bash
nix develop
cargo run
```

Для отдельной авторизации выполните `lavis auth`: если учётные данные ещё не настроены, команда проведёт настройку, затем авторизует Telegram и завершится. `lavis credentials` показывает только источник, наличие и путь к учётным данным, но не их значения.

`lavis credentials reset` запрашивает в интерактивном TTY подтверждение `[y/N]` и удаляет только `credentials.json`. Сеанс, настройки и псевдонимы сохраняются; после этого можно исправить учётные данные перед запуском `lavis auth`.

## Первая авторизация

1. Запустите `nix run github:zumuvik/lavis` или `lavis auth`.
2. При первом запуске введите API ID и API hash с my.telegram.org.
3. Введите номер телефона.
4. Введите код входа Telegram.
5. При необходимости введите пароль двухфакторной аутентификации.
6. После успешной авторизации локальный MTProto-сеанс будет использоваться при следующих запусках.

Код входа и пароль вводятся без отображения в терминале.

## Локальные данные

Lavis использует следующие файлы и каталоги:

- `$XDG_STATE_HOME/lavis/session`
- `$XDG_STATE_HOME/lavis/settings.json`
- `$XDG_STATE_HOME/lavis/aliases.json`
- `$XDG_STATE_HOME/lavis/external-modules.json`
- `$XDG_DATA_HOME/lavis/modules/`
- `$XDG_DATA_HOME/lavis/module-staging/`

Если соответствующая XDG-переменная не задана, используются `$HOME/.local/state/lavis/` и `$HOME/.local/share/lavis/`. `session` содержит секретный MTProto-сеанс; `external-modules.json` хранит набор включённых ID; `modules/` содержит установленный исполняемый код. `module-staging/` используется только для проверяемой установки и очищается best-effort при отмене, истечении approval, завершении и следующем запуске.

`lavis logout` запрашивает подтверждение и удаляет только локальный сеанс и его SQLite sidecar-файлы. Учётные данные, настройки, псевдонимы и установленные модули сохраняются; удаление не отзывает авторизацию на стороне Telegram.

## Префикс

Префикс по умолчанию — `,`. Он содержит от 1 до 4 символов Unicode, а не байтов, и не может включать буквы, пробельные символы, управляющие символы или невидимые символы форматирования. Изменение применяется сразу; `,prefix reset` возвращает запятую. Повреждённый файл настроек не перезаписывается автоматически.

## Псевдонимы

Синтаксис управления: `,alias`, `,alias list`, `,alias add <name> <command> [arguments...]`, `,alias show <name>`, `,alias del <name>`.

Имя приводится к нижнему регистру, имеет длину от 1 до 32 ASCII-символов, начинается с ASCII-буквы, а остальные символы могут быть ASCII-буквами, цифрами, `_` или `-`. Псевдоним может указывать только на канонические команды `ping`, `stats`, `help`, `modules` или `fastfetch`. `alias`, `prefix`, `setup` и `lm` недоступны в качестве целей. Канонические и зарезервированные имена нельзя переопределить; `modules` также запрещено и зарезервировано.

## Fastfetch

`fastfetch` показывает сведения о системе через строго ограниченный внутренний вызов. Это может раскрыть имя ОС, ядро, оборудование, оболочку, терминал и другие данные хоста всем, кто видит исходящее сообщение; используйте команду осознанно.

Грамматика команды (с текущим префиксом) только такая:

```text
,fastfetch [--no-profile] [--logo <logo>] [--structure <module:...>] [--separator <text>] [--logo-padding-left <n>] [--logo-padding-right <n>] [--logo-padding-top <n>]
```

- `--no-profile` отключает **всё** чтение профиля для этого запуска;
- `--logo` принимает только `none`, `Alpine`, `Arch`, `Debian`, `Fedora`, `FreeBSD`, `Linux`, `MacOS`, `NixOS`, `OpenBSD`, `Ubuntu` или `Windows`; ASCII-регистр не важен, а во внутренний вызов попадает каноническое написание;
- `--structure` — непустой список без повторов через `:`; ASCII-регистр не важен, порядок сохраняется, а во внутренний вызов попадают строчные ключи `title`, `separator`, `os`, `kernel`, `uptime`, `cpu`, `memory`, `gpu`, `packages`, `shell`, `terminal`, `terminalsize`, `host`, `display`, `wm`, `de`, `theme`, `icons`, `font`, `cursor`, `disk`, `swap`, `localip`, `battery`, `poweradapter`, `locale`;
- `--separator` — от 1 до 64 печатных ASCII-символов, не начинающихся с `--`;
- `--logo-padding-left <n>`, `--logo-padding-right <n>`, `--logo-padding-top <n>` — целое число от 0 до 32; каждое измерение независимо.

Пробелы и кавычки разбираются буквально как аргументы (`--separator " -> "`); оболочка не запускается, подстановка команд, переменных и другие shell-конструкции не выполняются. Позиционные аргументы, `--`, формы с `=`, повтор параметра, `--config`, профили/пресеты Fastfetch, произвольные типы логотипов и модули запрещены.

Lavis не добавляет логотип или структуру, если они не указаны явно в профиле либо команде; в таком случае используются собственные значения Fastfetch. Необязательный профиль пользователя находится только в `$XDG_CONFIG_HOME/lavis/fastfetch.json`, а при отсутствии `XDG_CONFIG_HOME` — в `$HOME/.config/lavis/fastfetch.json`. Это обычный локальный файл пользователя, не файл в Nix store и не часть пакета; Lavis его не создаёт.

Схема профиля строгая: версия только `1`, неизвестные поля запрещены, а `logo`, `structure`, `separator`, `logo_padding_left`, `logo_padding_right` и `logo_padding_top` необязательны; отсутствующие поля не добавляются Lavis. Если `structure` задана, она непуста, не содержит повторов и состоит только из перечисленных выше модулей. Файл ограничен 16 КиБ. Минимальный пример:

```json
{ "version": 1 }
```

Расширенный пример:

```json
{
  "version": 1,
  "logo": "NixOS",
  "structure": ["title", "separator", "os", "kernel", "cpu", "memory"],
  "separator": " -> ",
  "logo_padding_left": 2,
  "logo_padding_right": 3,
  "logo_padding_top": 1
}
```

Приоритет: значения Fastfetch по умолчанию < профиль < явные параметры команды. Символические ссылки и не-обычные файлы профиля не принимаются. Если профиль повреждён, недоступен или не проходит проверку, Fastfetch не запускается; исправьте или удалите локальный профиль либо временно используйте `,fastfetch --no-profile`. Сообщение об ошибке показывает только безопасную категорию и экранированный путь, а также направляет к `,help fastfetch`; содержимое профиля, системная ошибка и stderr Fastfetch не раскрываются. Расширенные модули могут раскрыть имя хоста, дисплей/DE/WM, тему, диски, локальный IP, батарею и питание — учитывайте видимость исходящего сообщения.

## Безопасность

- Команды принимаются из сообщений, автором которых является авторизованный аккаунт, включая собственные «Сохранённые сообщения», если Telegram помечает их как не исходящие.
- State-changing `lm install`, `lm confirm` и `lm cancel` выполняются только из нового собственного сообщения в «Сохранённых сообщениях»; редактирование старого сообщения не запускает установку.
- Lavis имеет полный доступ к Telegram-сеансу пользователя.
- Файл сеанса является чувствительным материалом аутентификации; MTProto-сеанс и API hash являются секретами.
- `.lmod` проходит структурную проверку и atomic no-overwrite install, но это не доказывает доверенность или безопасность кода.
- Внешние модули не изолируются системной песочницей и после включения работают с правами пользователя Lavis.
- Не запускайте недоверенные сборки и модули.
- Никогда не публикуйте API hash, базу данных сеанса или журналы терминала с учётными данными.
- Не публикуйте, не коммитьте и не передавайте локальные данные состояния.
- Код входа и пароль двухфакторной аутентификации не отображаются в терминале.
- Для обычной диагностики используйте `RUST_LOG=lavis=debug` вместо глобального отладочного логирования зависимостей: журналы зависимостей могут содержать данные Telegram.
